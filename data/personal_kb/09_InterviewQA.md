## 关于技术

### Q: 什么是 RAG？它解决了什么问题？
RAG（检索增强生成）是一种让大模型"开卷考试"的技术。传统 LLM 有两个问题：知识有截止日期、容易产生幻觉（编造信息）。RAG 的做法是：用户提问时，先到知识库检索相关文档，再把文档和问题一起发给 LLM，让 LLM 基于资料回答。这样就解决了知识更新和准确性的问题。

### Q: 向量检索和关键词检索有什么区别？
向量检索通过 Embedding 把文本转成数字向量，计算向量间距离来寻找语义相近的内容（能理解"续航"和"电池容量"是相关的）。关键词检索则直接匹配关键词（能精确找到"iPhone 15"这个型号）。两者互补，所以通常使用混合检索。

### Q: 你怎么评估 RAG 系统的质量？
三个维度：1）**检索质量**（找回来的文档是否相关）；2）**回答质量**（回答是否准确、完整、有来源引用）；3）**用户体验**（响应速度、流式输出、UI 交互）。目前主要通过人工评估，后续可以引入 RAGAS 等自动化评估框架。

### Q: 你遇到过什么技术难题？怎么解决的？
最难忘的是时区 bug：会话时间显示少了 8 小时。排查了前后端代码后发现，SQLite 不保存时区信息，SQLAlchemy 读出来后变成 naive datetime，前端当作本地时间解析。解决方案是后端自定义 UTCDateTime 类型补回 UTC 时区，前端也加了防御性解析。

## 关于项目

### Q: 你的 RAG 项目有哪些亮点？
1. **混合检索**：向量相似度 0.7 + 关键词匹配 0.3 加权融合
2. **流式输出**：WebSocket 逐字推送，体验流畅
3. **完整测试**：129 个 pytest 单元测试
4. **安全设计**：XSS 防护、bcrypt 加密、权限控制
5. **用户体验**：多会话管理、消息时间戳、文档处理轮询

### Q: 如果重新做这个项目，你会怎么改进？
1. 引入 Rerank 模型（如 Cohere Rerank）提升检索排序质量
2. 支持多模态（图片、表格等更多格式）
3. 用 PostgreSQL 替代 SQLite，用 Redis 做缓存
4. 引入异步任务队列（Celery）处理大批量文档
5. 加上 AI Agent 能力（主动追问、多步推理）
6. 完善监控和日志（Prometheus + Grafana）

### Q: 你对 LangChain 框架怎么看？
LangChain 是目前最流行的 LLM 应用开发框架，优点是抽象程度高、组件丰富、社区活跃。但也有一些问题：版本更新频繁 API 不稳定、文档不够完善、某些抽象层过度设计。我使用 LangChain 但不依赖它——理解底层原理后，即使换框架也能快速上手。
